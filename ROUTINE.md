Write today's Proverbs study into this repo and push it to main. GitHub Pages publishes it to https://jondipilato.github.io/proverbs-study/ on its own. A FRESH passage and a FRESH focus word every day — never re-teach a verse or re-use a focus word.

HARD RULES: Write exactly ONE new file, `_posts/<date>-proverbs-<CH>-<V>.md`. Never edit, rename, or delete any other file. Never type scripture or Hebrew from memory — copy it from `scripts/study.py verse`. If any step says STOP, end the run and report the reason in plain words; never publish around a failure.

0. DATE. TODAY=`TZ=America/New_York date +%F`, CH=`TZ=America/New_York date +%-d` (Proverbs has 31 chapters, so the chapter follows the calendar), WEEKDAY=`TZ=America/New_York date +%A`, MONDD=`TZ=America/New_York date +'%b %d'`. If any `_posts/$TODAY-*.md` already exists, STOP: "today's study already exists: <file>".

1. PICK THE PASSAGE. Run `python3 -c "import yaml" || pip install pyyaml`, then `python3 scripts/study.py coverage $CH`. It prints the ranges of chapter CH already covered, the verses still free, and every focus word already used. If it prints CHECK FAILED, or says the chapter is fully covered, STOP and report what it printed. Otherwise pick ONE tight, contiguous cluster of 1–4 FREE verses with a strong practical theme (work, money, speech, temptation, family, planning, anger, laziness).

2. GET THE TEXT. Run `python3 scripts/study.py verse $CH:<V or V1-V2>`. It prints the exact King James text and every Hebrew word of the passage with its Strong's number, from the public-domain KJV and the Open Scriptures Hebrew Bible vendored in `scripts/data/`. Copy the KJV text exactly, character for character.

3. THE WORD STUDY. From that printout choose 3–6 load-bearing Hebrew words. For each row copy the `hebrew` value and its `strongs` EXACTLY as printed (one word per row — no spaces, slashes, or phrases; use a `parts` piece when a prefix like וְ or בְּ is attached and you are teaching only the main word). Then use WebSearch to learn each word's meaning: the Strong's number plus "Hebrew" against a reputable concordance (Blue Letter Bible, StudyLight, Bible Hub). `translit` = a plain transliteration of the word as printed. `meaning` = start with a short plain-English gloss (a few words, e.g. "anxiety, worry"), then " — " and what it adds to the verse. Mark 1 or 2 rows `focus: true` — the words the whole study turns on. A focus word must NOT be in coverage's "already used" list.

4. WRITE THE FILE. Set FILE=`_posts/$TODAY-proverbs-$CH-<V or V1-V2>.md` and write it. Open the newest file in `_posts/` and match its front matter shape exactly: title (the theme, no reference), reference ("Proverbs CH:VV"), chapter (int), verses ("V" or "V1-V2", same as the file name), hook (one line), kjv (one item per verse, in order: ref "CH:V", text), words (hebrew, strongs, translit, meaning, focus on 1–2), word_note (the "what it means" paragraph; *italics* allowed), actions (EXACTLY 3), prayer, and the body after the front matter = "what this actually means" prose. No other front matter keys. Double-quote every YAML string and escape inner double quotes as \". Never use `{{` or `{%`. Voice: plain everyday 5th-grade language, short punchy sentences, no churchy or corporate filler, written like a plain-spoken friend to a working man. Each action = one concrete thing to DO today to obey these specific verses, doable before noon, in a real situation (work, money, family, speech, temptation, the phone) — never vague like "be kind", concrete like "when a client pushes back today, give the soft answer first, then the fact." Prayer = one honest sentence asking God for help to obey this today.

5. CHECK. Run `python3 scripts/study.py check --new $FILE`. It must print CHECK PASSED. It verifies the date, the KJV wording, that every Hebrew row is a real word of the passage with its real Strong's number, and that no verse or focus word repeats. If it fails, fix $FILE and run it again. Never touch another file to make it pass.

6. PUBLISH. `git add $FILE` (only that file), then `git commit -m "Proverbs CH:VV — <title> (<WEEKDAY>, <MONDD>)"` — the message is that ONE line only: no Co-Authored-By, no Claude-Session, no "Generated with" footer, no trailers of any kind (the repo owner forbids AI branding on commits). Then `git push origin HEAD:main`. If the push is rejected: `git pull --rebase origin main`, run step 0's existence check and step 5's check AGAIN (another run may have published today), and only if both pass push once more. If anything still fails, STOP and report the exact error loudly — do NOT claim success.

7. CONFIRM IT IS LIVE. The page URL is https://jondipilato.github.io/proverbs-study/YYYY/MM/DD/<file name without the date and .md>/ . Pages takes 1–3 minutes to rebuild. Check it with `curl -s -o /dev/null -w "%{http_code}" "<url>?t=$(date +%s)"` every 30 seconds for up to 6 minutes. If it returns 200, report LIVE. If this environment cannot reach github.io at all, report "pushed, live check UNVERIFIED (no network to github.io)". If it reaches github.io but never returns 200, report "PUSHED BUT NOT LIVE" loudly — the site build likely failed.

8. REPORT the file name, verse range, focus word(s), commit hash, page URL, and the step 7 result.
