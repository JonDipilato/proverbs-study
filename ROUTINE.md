Write today's Proverbs study into this repo and push it to main. GitHub Pages publishes it to https://jondipilato.github.io/proverbs-study/ on its own. A FRESH passage and a FRESH focus word every day — never re-teach a verse or re-use a focus word.

HARD RULES: Write exactly ONE new file, `_posts/<date>-proverbs-<CH>-<V>.md`. Never edit, rename, or delete any other file. Never quote scripture or Hebrew from memory.

0. DATE. TODAY=`TZ=America/New_York date +%F`, CH=`TZ=America/New_York date +%-d` (Proverbs has 31 chapters, so the chapter follows the calendar), WEEKDAY=`TZ=America/New_York date +%A`. If any `_posts/$TODAY-*.md` already exists, STOP and report "today's study already exists: <file>". Do not write a second one.

1. PICK THE PASSAGE. Run `python3 -c "import yaml" || pip install pyyaml`, then `python3 scripts/study.py coverage $CH`. It prints the verse ranges of chapter CH already covered and every focus word already used. From chapter CH pick ONE tight, contiguous verse cluster (1–4 verses) that overlaps NONE of the covered ranges, with a strong practical theme (work, money, speech, temptation, family, planning, anger, laziness). If `coverage` prints CHECK FAILED, STOP and report the errors — do not write anything.

2. GET THE EXACT TEXT. Use WebSearch to get the KJV text of the chosen verses and cross-confirm the exact wording from at least TWO independent live sources in the results. (WebFetch to bible sites is blocked by this environment's egress proxy; WebSearch works.) If you cannot cross-confirm the wording from two live sources, STOP and report the error loudly.

3. THE WORD STUDY. Open up the load-bearing Hebrew words of the passage (3–6 rows). Verify every row via WebSearch (the word plus "Strong's Hebrew Proverbs CH:V"; confirm Strong's number, Hebrew spelling, transliteration, and root meaning against at least one reputable concordance such as Blue Letter Bible or StudyLight). If a word cannot be verified, drop it. NEVER invent Hebrew, vowel pointing, or Strong's numbers. Mark 1 or 2 rows `focus: true` — the words the whole study turns on. A focus word must NOT be in coverage's "already used" list.

4. WRITE THE FILE `_posts/$TODAY-proverbs-$CH-<V or V1-V2>.md`. Open the newest file in `_posts/` and match its front matter shape exactly: title (the theme, no reference), reference ("Proverbs CH:VV"), chapter (int), verses ("V" or "V1-V2", same as the file name), hook (one italic-style line), kjv (one item per verse: ref "CH:V", text), words (hebrew, strongs, translit, meaning, focus on 1–2), word_note (the "what it means" paragraph; *italics* allowed), actions (EXACTLY 3), prayer, and the body after the front matter = "what this actually means" prose. Double-quote every YAML string and escape inner double quotes as \". Voice: plain everyday 5th-grade language, short punchy sentences, no churchy or corporate filler, written like a plain-spoken friend to a working man. Each action = one concrete thing to DO today to obey these specific verses, doable before noon, in a real situation (work, money, family, speech, temptation, the phone) — never vague like "be kind", concrete like "when a client pushes back today, give the soft answer first, then the fact." Prayer = one honest sentence asking God for help to obey this today.

5. CHECK. Run `python3 scripts/study.py check --new <your file>`. It must print CHECK PASSED. If it fails, fix YOUR file and run it again. Never touch another file to make it pass.

6. PUBLISH. `git add <your file>` (only that file), `git commit -m "Proverbs CH:VV — <title> (<WEEKDAY>, <Mon DD>)"` — the message is that ONE line only: no Co-Authored-By, no Claude-Session, no "Generated with" footer, no trailers of any kind (the repo owner forbids AI branding on commits), `git push origin HEAD:main`. If the push is rejected, `git pull --rebase origin main` and push once more. If it still fails, STOP and report the exact error loudly — do NOT claim success.

7. REPORT the file name, verse range, focus word(s), the commit hash, and the page URL: https://jondipilato.github.io/proverbs-study/YYYY/MM/DD/<file-name-without-date-and-.md>/ (Pages takes about a minute to rebuild after the push).
